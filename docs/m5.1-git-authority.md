# M5.1 trusted Git authority and deferred plan

M5.1 adds read-only trusted Git observation and an immutable, data-only Git
effect plan. It does not create commits, objects, branches, refs, remote
requests, pushes, or pull requests.

## Trust boundary

The real repository and its `.git` directory remain trusted host objects. The
hostile sandbox receives neither one. The disposable workspace still excludes
`.git`, credential files, `.env` files, and the other M4 exclusions. A `.git`
directory created by the agent in its disposable workspace is ordinary hostile
final-state data: reconciliation observes it and the one-file M4 policy rejects
the extra mutation. It can never become repository identity.

`Lifecycle.BindGitRepository` is accepted only in `CREATED`, before sandbox
preparation or execution. `Lifecycle.DeriveGitEffectPlan` is accepted only in
`VERIFIED`. Neither method changes lifecycle state or invokes a Git mutation.

## Supported repository shape

M5.1 v0 intentionally accepts only a narrow repository topology:

- one non-bare worktree with an attached `refs/heads/*` HEAD;
- a physical, non-symlink repository root;
- a physical `.git` directory directly below that root;
- SHA-1 Git object format;
- a bounded regular `.git/config` and `.git/index`;
- no gitfile or linked-worktree indirection;
- no `commondir`, per-worktree administrative store, submodule administrative
  store, alternate object database, config include, or configured external
  worktree;
- a clean tracked worktree and index relative to the bound HEAD.
- only ordinary stage-0 regular-file index entries, with no `skip-worktree`,
  `assume-unchanged`, sparse-checkout, gitlink, or conflicted-stage state.

Read-only observations use Git argv execution, not shell interpolation. Output
is bounded, human-facing output is not parsed, optional locks and prompting are
disabled, replacement objects are ignored, and the child environment is an
allowlist that excludes credentials and Git authority overrides.

The binding records the physical repository root and `.git` identity privately
for `os.SameFile` revalidation, plus exact HEAD commit, HEAD tree, attached ref,
index digest, configuration digest, repository identity, manifest identity,
trusted capture time, and a canonical binding hash. Capture performs two full
observations and rejects a change between them.

## Dirty and excluded-file policy

Tracked worktree changes and index changes relative to HEAD are rejected. They
would make the history base ambiguous.

Untracked files are not Git-history authority in M5.1. The M4 workspace scanner
still determines which non-secret real files form the disposable baseline and
its complete final-state reconciliation. Existing source exclusions (`.git`,
`.env*`, SSH/cloud credential locations, and configured credential files) are
not copied to the agent and do not become Git plan effects. M5.1 does not claim
freshness for excluded host files; it binds Git history and MIRAGE's separately
verified M4 filesystem plan.

## Deferred Git effect plan

The plan derives its exact file effects only from the allowed reconciliation
plan and decision. M5.1 retains the existing commit shape:

```text
one existing regular-file content MODIFY
```

It rejects CREATE, DELETE, MODE_CHANGE, links, special objects, and multiple
mutations. Agent stdout, explanations, prompts, patches, status output, commits,
and shadow `.git` state are never plan authority.

The plan binds:

- version, run ID, manifest hash, contract hash, and contract expiry;
- repository binding and repository identity;
- exact base commit, base tree, and attached base ref;
- verified reconciliation plan hash and authority hash;
- the exact normalized mutation set;
- a deterministic `refs/heads/mirage/run-<hash>` target that contains no raw
  user-controlled ref text;
- fixed trusted author identity, a deterministic bounded message, and trusted
  creation time;
- a canonical plan identity.

Revalidation repeats physical repository identity, layout, cleanliness, HEAD,
tree, ref, index, config, manifest, contract, trusted time, reconciliation, and
plan-identity checks. A mismatch fails closed. It never regenerates authority
from newly observed state. A detected repository mismatch makes the trusted
lifecycle `CONFLICTED`; the plan cannot be retried in that lifecycle even if an
outside process later restores the old ref bytes.

## Exact guarantee and limitations

M5.1 can prove which clean, ordinary Git history and which MIRAGE-verified
single-file mutation a future executor is authorized to consume. M5.1 performs
zero real Git mutations.

It does not yet construct a Git commit, write an object, alter an index or ref,
create a branch, contact a remote, handle credentials, push, call GitHub, create
a pull request, provide crash recovery, or claim atomicity across external
systems. Those capabilities require separate M5.2-M5.4 security reviews.
