# M5.3 create-only GitHub publication

M5.3 adds one external effect to the closed M5.2 boundary: create one exact
run-scoped branch in one exact github.com repository, pointing to the exact
M5.2 commit. It does not create pull requests, update or delete branches,
create tags, retry an uncertain push, or modify the real local repository.

## Contract v2 authority

`mirage.contract/v1` keeps its original canonical JSON and hashes and always
denies GitHub publication. `mirage.contract/v2` retains the filesystem policy
and adds exactly:

```text
github_publication:
  repository_full_name: mrgray17/mirage-test
  target_ref: refs/heads/mirage/run-<24 lowercase SHA-256 hex characters>
  operation: CREATE_BRANCH
```

Repository identity is lower-case canonical `owner/repo` data for github.com,
not a URL. Schemes, userinfo, queries, fragments, traversal, control characters,
extra path segments, arbitrary hosts, SSH, and empty/oversized names fail
closed. The target ref must equal the shared M5.1-compatible deterministic
derivation for the contract run ID. Main, master, tags, arbitrary refs,
updates, and deletion are not representable authority.

## Binding and plan

Before hostile execution, the lifecycle binds the local Git repository and
then uses a fixed-origin, read-only GitHub API client to bind:

- `provider = github.com`;
- canonical repository full name and stable numeric GitHub repository ID;
- contract and manifest hashes;
- trusted capture time and canonical binding identity.

The API client refuses redirects and proxies, applies connection, TLS,
response-header, overall request, context, and one-MiB body bounds, validates
expected status/JSON semantics, and exposes only repository and exact-ref
reads. Git config never chooses the remote.

After verified reconciliation and M5.2 construction, one immutable
`GitPublicationPlan` binds the manifest, contract, local repository binding,
Git effect plan, commit artifact and exact commit OID, base ref and base commit,
GitHub binding/ID/full name, target ref, `CREATE_BRANCH`, trusted creation time, and a
canonical identity. It contains no credential, filesystem transaction path,
agent text, URL, or ambient configuration. Repeated derivation freshly
revalidates authority and returns the same plan.

## Credential and process boundary

Only `MIRAGE_GITHUB_TOKEN` is accepted, and only by trusted host code. There is
no fallback to `gh`, Git credential helpers, SSH agents, `.netrc`, HOME config,
origin credentials, `GITHUB_TOKEN`, or `GH_TOKEN`. The token is supplied to a
secret-free, protected askpass helper through the trusted Git child environment;
it is never placed in argv, a URL, Git config, plans, records, errors, captured
output, or temporary files. Docker subprocess environment scrubbing prevents
the host token from reaching the sandbox.

The trusted Git environment disables system/global config, credential helpers,
terminal prompts, hooks, replacement objects, lazy fetch, SSH, redirects,
implicit protocol selection, tag following, and submodule recursion. The
remote is constructed only as
`https://github.com/<canonical-owner>/<canonical-repository>.git`.

## Publication workspace and exact push

M5.3 creates a protected `.mirage-m53-*` host temporary workspace with a
minimal bare administrative area, empty HOME/hooks directories, and no index,
worktree, remote config, credential, or real-repository hook. Only M5.2's exact
loose objects are exported into its object directory; the trusted real object
database is a read-only logical alternate. MIRAGE verifies that the publication
view resolves the exact commit, tree, and parent before dispatch. Export and
workspace scans impose a 96-MiB/100,000-entry logical bound, reject links and
special objects, and fail on physical root replacement. All Git temporary paths
are directed into the protected workspace.

The only mutation argv contains one explicit refspec:

```text
<CommitOID>:<TargetRef>
```

and the atomic nonexistence expectation:

```text
--force-with-lease=<TargetRef>:
```

The empty expected value is an exact compare-and-swap requirement that the
remote ref does not exist. This is not general force-push authority. Local bare
remote tests prove that a ref created after preflight cannot be overwritten.

Immediately before starting that one push process, a mandatory lifecycle
callback repeats trusted-time, manifest, filesystem decision, local Git
binding/plan, real baseline, frozen shadow, commit artifact, GitHub binding,
the exact remote `BaseRef -> BaseCommit`, publication plan, exact operation,
repository, target ref, and commit checks. A stale
artifact pointer is powerless outside this path.

## Network outcome state machine

M5.3 authorizes at dispatch time. It does not claim a remote server applied the
ref before a globally atomic wall-clock expiry instant.

The lifecycle performs at most one mutation attempt. Regardless of process
exit, it reads the authoritative exact remote ref and records transport
acknowledgement separately from observed truth:

```text
PUBLISHING
  exact ref == CommitOID  -> PUBLISHED
  exact ref == other OID  -> CONFLICTED
  exact ref absent        -> FAILED / NOT_PUBLISHED
  exact ref unavailable   -> PUBLICATION_UNCERTAIN
```

`PUBLICATION_UNCERTAIN` forbids another push. Only read-only
`ReconcileGitPublication` is permitted; exact becomes `PUBLISHED`, absent is
terminal not-published, another OID is `CONFLICTED`, and unavailable remains
uncertain. A lost acknowledgement followed by the exact OID proves desired
state but does not claim transport acknowledgement or exclusive causality.
An exact branch that existed before MIRAGE's first attempt is a conflict, not a
MIRAGE publication. After `PUBLISHED`, repetition performs only fresh authority
and remote-drift reads and returns the same record. Moved/deleted refs are never
repaired automatically.

The immutable `PublicationRecord` binds the complete plan/artifact/destination,
attempt and dispatch identities, transport outcome, authoritative observed ref
and OID, acknowledgement/reconciliation facts, final outcome, and its own
canonical identity. Local cleanup failure is reported but cannot hide known
remote truth. No compensating branch deletion exists.

## Exact guarantee and limitations

For the supported M5.3 state model, MIRAGE proves:

- the bound GitHub repository already exposes the trusted local base commit at
  the exact trusted base branch before authority is installed, during publisher
  preflight, and immediately before dispatch; M5.3 therefore cannot be the
  mechanism that first exports pre-existing local-only history;

```text
remote effect <= one create-only attempt for exact TargetRef -> exact CommitOID
real local worktree/index/HEAD/refs/reflogs/config/object bytes after == before
```

The remote ref is authoritative after dispatch; Git process exit is not. A
non-cooperating remote/network can leave the lifecycle uncertain until a later
read succeeds. GitHub and local filesystem observations are not one globally
atomic transaction. The trusted host, MIRAGE process, OS, Go HTTP/TLS stack,
Git binary, DNS/TLS trust roots, github.com, and dedicated credential remain in
the trusted computing base. The publication workspace is logically bounded but
does not provision a separate crash-durable filesystem quota. Crash-durable
records, signed receipts, automatic recovery across process restart, SHA-256
Git object format, GitHub Enterprise, proxies, and multi-file/history widening
remain out of scope.

Live GitHub testing is disabled unless all of `MIRAGE_M53_LIVE=1`,
`MIRAGE_M53_TEST_REPO`, `MIRAGE_M53_TEST_REPO_ROOT`, and
`MIRAGE_GITHUB_TOKEN` are set intentionally. The repository root must be a
clean trusted checkout whose attached base ref and HEAD already exist exactly
in the dedicated GitHub repository. The live test creates exactly one uniquely
named run branch, creates no PR, performs no automatic deletion, and never
falls back to ambient credentials.
