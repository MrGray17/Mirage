# MIRAGE security regression matrix

**Purpose:** make each important security claim reviewable against concrete regression tests and the gate that executes them. This is a test map, not a blanket security certification. Test names show intended failure modes; the execution level matters just as much as the name.

## Evidence levels

| Level | What runs | Meaning |
|---|---|---|
| Standard CI | `gofmt`, `go vet ./...`, `go test -race -count=1 -cover ./...`; Windows CLI frontend tests/build | Reproducible unit, state-machine, policy, parser, installer, and platform checks. Opt-in runtime tests are not automatically enabled by the ordinary Go suite. |
| Live Linux acceptance | `./scripts/test-live.sh` with digest-pinned fixture images and rootless Docker | The script repeats standard checks, then enables the real-runtime Docker and demo acceptance tests. Requires Go 1.27.3+, rootless Docker, cgroup v2/systemd, seccomp, and delegated resource controllers. |
| Separate external-effect acceptance | `MIRAGE_M53_LIVE=1 go test -race -count=1 -v -run '^TestM53LiveGitHubCreateOnlyPublication$' ./internal/runtime` | Creates a real branch in a disposable remote repository. This is intentionally outside the default/live runtime gate and is **not marked passed** by the current evidence. |
| Separate provider-backed run | A deliberately configured agent/provider request in a throwaway workspace | May use external credentials or incur cost. It is not run by `scripts/test-live.sh`; unit tests of the broker do not substitute for a live provider-backed run. |

GitHub authority is constrained by `TestContractV2AuthorizesOnlyExactGitHubCreateBranch` and `TestContractV2RejectsUntrustedGitHubDestinationForms`. | Standard CI. Proves the tested contract rules and input cases, not correctness of every possible policy a user may write. |

The live coding-agent cases also test direct writes, additional files, two edits where only one is allowed, and late background writes. |

| **The hostile runtime cannot reach the real workspace, host secrets, or Docker socket through the configured sandbox.** | `TestRootlessDockerContainsHostileFixture` in [Docker integration tests](../internal/runtime/docker/launcher_integration_test.go); `direct_host_secret_network_and_Docker_socket_probes_stay_absent` subtest inside `TestRootlessCodingAgentUsesFrozenQuotaVolumeAndNarrowCommit`; `TestRootlessSandboxCanTraverseButNotListOrWriteBrokerDirectory` in [broker-connect integration tests](../internal/runtime/docker/broker_connect_integration_test.go). | Live Linux acceptance. A failed request by itself is not a proof of isolation. |
| **The trusted workspace changes only at the approved commit boundary.** Rejected shadow state is discarded; a conflicting real change or a post-verification shadow mutation blocks replacement. | `TestShadowWriteLeavesRealWorkspaceUnchanged`, `TestRejectDiscardsShadowAndPreservesRealWorkspace`, `TestApplyCommitIsTheOnlyPointRealWorkspaceChanges`, `TestApplyCommitDetectsExternalModificationConflict`, `TestConflictNeverAppliesShadowContentsToRealWorkspace` in [shadow transaction tests](../internal/runtime/shadowfs/transaction_test.go); `TestUnobservedShadowMutationWithoutApprovedWriteRejectsVerification`, `TestPostVerificationShadowMutationRejectsCommit` in [run commit-binding tests](../internal/runs/commit_binding_internal_test.go). | Standard CI tests the transition logic; `TestRootlessDockerCommitsOneVerifiedRealFile` and the live agent integration run exercise the real Docker/commit path. |

| **The supported filesystem commit is narrow and tied to the exact approved diff.** Multiple changes cannot widen a one-file authority; a no-op does not needlessly replace the real file. | `TestAllowedFilesystemEffectsVerifyAndCommit`, `TestAuthorizedWriteWithNoFinalDiffDoesNotReplaceReality` in [run tests](../internal/runs/run_test.go) and [no-op tests](../internal/runs/noop_write_internal_test.go); `TestLifecycleRejectsTwoFileCommitPlanWithoutTouchingReality`, `TestLifecycleCommitsOneVerifiedContentChangeAndPreservesRealMode`, `TestLifecycleRejectsRealChangeImmediatelyBeforeCommit`, `TestLifecycleRejectsShadowChangeAfterVerification` in [lifecycle tests](../internal/runtime/lifecycle_test.go). | Standard CI plus live Linux acceptance. ## Explicit gaps and limits

- **WSL2-specific acceptance remains unverified.** The recorded live run is hosted Linux rootless Docker, not the user's own Windows/WSL2 installation.
- **Live GitHub branch creation remains untested.** Existing unit tests do not count as proof that the external write path succeeded against GitHub. Use only a disposable repository and narrowly scoped credentials if this separate test is authorized.
- **No paid/provider-backed model request is claimed.** Broker/policy tests run without proving a real external provider response path.
- **No syscall-perfect audit.** Tool and broker events are not universal syscall telemetry; the security decision relies on trusted final-state reconciliation after verified stop/freeze.
- **Single-file scope only.** No general multi-file atomic commit, file creation/deletion, permission-mode change, symlink/hard-link commit, or full preservation of ACLs/xattrs/ownership is promised.
- **Residual host races remain.** In particular, the final revalidation-to-replacement window against a non-cooperating host process is documented; the current design does not claim host-level transaction isolation.
- **Evidence is not signed attestation.** Hashes detect many accidental/structural modifications but do not prove truth against a compromised host.
- **Current main does not include a crash-durable commit journal.** Do not describe the local replacement path as crash-recoverable or as a general transaction log.

## Change policy

When a security claim changes, update the relevant row and add or strengthen a test in the same change. A regression is not considered covered merely because an adjacent test passes. When an anchor is renamed or removed, update this matrix. Keep unit/CI results, live-runtime results, live external-effect results, and provider-backed results clearly separate in review notes and competition material.
